# API Contract

> Snapshot of the Confluence page [API Contract](https://annaseku01.atlassian.net/wiki/spaces/Crawlers/pages/20742145), taken 23 October 2026. The live page needs an Atlassian login. The client is referred to by role, not by name.

# 1. Overview 

This document defines the agreed API contract between Find Me Funding frontend and backend applications. 

The purpose of the API to allow React Frontend to submit a user’s funding search criteria to the Python (Library/Framework) Backend and receive a ranked list of relevant funding opportunities. 

This document defines:

* Available API endpoints
* Request and response formats
* Required and optional parameters
* Data types
* Error handling
* HTTP status codes
* Naming conventions

The API contract should be treated as the agreed interface between the frontend and backend teams. Internal implementation details may change without requiring changes to this document, provided the external API contract remains unchanged.

# 2. Architecture

The application consists of two primary components:

| Component | Technology | Responsibility |
| --- | --- | --- |
| Frontend | React | Collect user input and display funding results |
| Backend | Python | Process searches, retrieve funding opportunities, rank results and provide API responses |

**Basic Request Flow**

User  
 ↓  
React Frontend  
 ↓  
HTTP Request  
 ↓  
Python Backend API  
 ↓  
Search / Filtering / Ranking  
 ↓  
JSON Response

# 4. API Conventions

### Request format

Requests containing data should use:

```
Content-Type: application/json
```

### Response format

All API responses should use:

```
application/json
```

### Naming convention

JSON fields will use **snake_case**.

Example:

```json
{
  "field_of_research": "Computer Science",
  "career_stage": "Graduate Student"
}
```

rather than:

```json
{
  "fieldOfResearch": "Computer Science",
  "careerStage": "Graduate Student"
}
```

### Dates

Dates should use:

```
YYYY-MM-DD
```

Example:

```
2026-10-15
```

# 5. Search Funding Opportunities

## `POST /api/search`

### Description

Submits the user's selected search criteria and returns a ranked list of relevant funding opportunities.

The frontend should send the search criteria collected from the search form.

---

## Request Body

```json
{
  "field_of_research": "Computer Science",
  "activity_type": "Research",
  "citizenship": [
    "Australia"
  ],
  "employer_type": "University",
  "career_stage": "Graduate Student",
  "funding_type": "Equipment",
  "keywords": "artificial intelligence"
}
```

---

## Request Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `field_of_research` | String | Yes | User's selected Field of Research |
| `activity_type` | String | Yes | Type of research/activity |
| `citizenship` | Array\[String\] | Yes | One or more citizenships |
| `employer_type` | String | Yes | User's employer/institution type |
| `career_stage` | String | Yes | User's career stage |
| `funding_type` | String | Yes | Type of funding required |
| `keywords` | String | No | Free-text search terms |

> **Note:** Whether each field is ultimately required should be confirmed with the backend team. The frontend may allow optional fields if the search algorithm supports them.

```json
{
  "results": [

      "relevance_score": 0.92,
```

# 7. Funding Result Object

Each funding opportunity returned by the API should contain the following information.

| Field | Type | Description |
| --- | --- | --- |
| `id` | String | Unique identifier for the funding opportunity |
| `title` | String | Name of the funding opportunity |
| `provider` | String | Organisation providing the funding |
| `description` | String | Short description of the opportunity |
| `amount` | Number | Maximum or advertised funding amount |
| `deadline` | String | Application deadline in `YYYY-MM-DD` format |
| `eligibility` | String | Eligibility assessment |
| `relevance_score` | Number | Relevance score generated by the ranking system |
| `url` | String | Link to the original funding opportunity |

---

# 8. Eligibility

The backend will provide an eligibility assessment for each funding opportunity.

Initially, the following values will be used:

```
Likely eligible
Eligibility unknown
Likely not eligible
```

The frontend will display this information to the user.

> **Open Question:** Confirm whether eligibility should eventually be represented as an enum/code rather than a display string.

For example:

```json
{
  "eligibility": "likely_eligible"
}
```

could be preferable internally, with the frontend converting this to:

```
Likely eligible
```

---

# 9. Ranking

Funding opportunities will be ranked by the backend.

The frontend **will not independently calculate the ranking**.

The backend ranking system may consider factors including:

*  Eligibility 
*  Relevance to the user's search 
*  Funding amount 
*  Application deadline 
*  Other relevant ranking criteria 

The API will return the opportunities in their ranked order.

Example:

```json
{
  "results": [
    {
      "id": "123",
      "relevance_score": 0.95
    },
    {
      "id": "456",
      "relevance_score": 0.81
    },
    {
      "id": "789",
      "relevance_score": 0.63
    }
  ]
}
```

The frontend should display the results in the order provided by the backend unless otherwise agreed.

# 11. Error Handling

The API should return an appropriate HTTP status code and a JSON error response when a request cannot be completed.

### Example

```json
{
  "error": "Invalid search parameters"
}
```

### HTTP Status Codes

| Status | Meaning | Example |
| --- | --- | --- |
| `200` | Success | Search completed successfully |
| `400` | Bad Request | Invalid or missing parameters |
| `404` | Not Found | Funding opportunity does not exist |
| `500` | Internal Server Error | Unexpected backend error |

---

# 12. Empty Search Results

If a search is valid but no relevant funding opportunities are found, the API should return:

### HTTP `200 OK`

```
{
  "results": []
}
```

The frontend will then display an appropriate message to the user, for example:

> **No funding opportunities found.**  
>  Try changing your search criteria.

An empty search result should **not** be treated as an API error.

---

# 13. Validation

The backend is responsible for validating incoming API requests.

Examples of invalid requests include:

*  Invalid field values 
*  Incorrect data types 
*  Missing required parameters 
*  Malformed JSON 

Example:

```json
{
  "error": "Invalid career_stage value"
}
```

The frontend should display an appropriate error message rather than attempting to interpret or correct backend validation errors.

---

# 14. Frontend Responsibilities

The React frontend is responsible for:

*  Collecting user search criteria 
*  Validating basic user input 
*  Sending API requests 
*  Displaying loading states 
*  Displaying search results 
*  Displaying API errors 
*  Displaying empty search results 
*  Linking users to the original funding opportunity 

The frontend should **not** be responsible for:

*  Scraping funding websites 
*  Determining eligibility 
*  Ranking funding opportunities 
*  Modifying funding data returned by the backend 

---

# 15. Backend Responsibilities

The Python backend is responsible for:

*  Receiving search requests 
*  Validating API requests 
*  Searching funding sources 
*  Processing funding opportunities 
*  Determining/estimating eligibility 
*  Calculating relevance/ranking 
*  Returning structured JSON responses 
*  Handling backend errors
