## Channels

**Team: confirm or correct this table.** Document the channels we actually use, not the ones we intend to. A plan that describes real behaviour is worth more than an aspirational one.

| Channel | Used for | Response expectation |
| --- | --- | --- |
| **Slack** | Day-to-day coordination, quick questions, blockers, sharing links. The default place to talk. | Within a working day; flag urgent items with `@here` |
| **Jira (KAN board)** | What everyone is working on and what state it is in. The board is the source of truth for task status — not Slack, not memory. | Update your card when its state changes |
| **GitHub** | Code, pull requests and code review discussion. Review comments stay on the PR so they are attached to the change. | Review within one working day of a PR opening |
| **Confluence** | Decisions, requirements, architecture, sprint and meeting records. Anything that should outlive a conversation. | Written up within two days of the discussion |
| **Email** | Client contact with the client and correspondence with the supervisor. | Logged on the Client Communication Log after sending |
| **In person / scheduled calls** | Standups, sprint ceremonies, client meetings. | Notes published to Confluence afterwards |

## The routing rule

One sentence, so nobody has to guess:

> If it changes what someone should _do_, it goes on the **board**. If it changes what the team _knows_, it goes in **Confluence**. Everything else is **Slack**.

The failure mode this prevents is a decision made in a Slack thread that never reaches Confluence, so it has to be re-litigated a fortnight later by whoever missed it.

## Cadence

| Event | Frequency | Who | Output |
| --- | --- | --- | --- |
| Standup | Per the team's agreed schedule | Whole team | Entry on the standup summaries page |
| Sprint planning | Start of each sprint | Whole team | Sprint planning page, cards on the board |
| Sprint review | End of each sprint | Whole team | Sprint review page |
| Sprint retrospective | End of each sprint | Whole team | Retrospective page with actions carried into the next sprint |
| Client check-in | To be agreed — supervisor has asked us to meet the client more often | Nominated members | Meeting notes, logged on the Client Communication Log |

## Escalation

If you are blocked for more than half a working day, say so in Slack rather than waiting for the next standup. A blocker held quietly for two days costs the sprint more than an interruption costs anyone's afternoon.
