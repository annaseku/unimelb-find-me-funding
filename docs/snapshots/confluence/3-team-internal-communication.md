# 3. Team Internal Communication

> Snapshot of the Confluence page [3. Team Internal Communication](https://annaseku01.atlassian.net/wiki/spaces/Crawlers/pages/10616834), taken 23 October 2026. The live page needs an Atlassian login. The client is referred to by role, not by name.

**Progress Checklist item 3 (Process).** How the team talks to itself: which channel carries what, how fast we respond, and how blockers surface. The Week 1 lecture: communicate regularly, and document all team meetings and decisions.

## Channels and routing

The [Communication Plan](communication-plan.md) (child page) sets the rule: if it changes what someone should do, it goes on the KAN board; if it changes what the team knows, it goes in Confluence; everything else is Slack.

| Channel | Carries |
| --- | --- |
| Slack | Day-to-day coordination, questions, blockers |
| [KAN board](https://annaseku01.atlassian.net/jira/software/projects/KAN/boards) | Task ownership and status |
| GitHub pull requests | Code review discussion, attached to the change |
| Confluence | Decisions, requirements, meeting and sprint records |
| Workshop standups | Weekly sync with the supervisor ([Standup Summaries](standup-summaries.md)) |

## Evidence of it working

* The Sprint 2 retrospective named communication as the main problem and set actions: GitHub PR workflow, Slack channels for updates and reviews, recorded meetings ([Sprint 2 Retrospective](sprint-2-retrospective.md)).
* Week 9 tutor feedback: "team communicates well" ([Standup Summaries](standup-summaries.md)).
